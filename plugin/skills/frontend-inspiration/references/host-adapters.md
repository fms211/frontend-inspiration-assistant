# 宿主能力适配

## 能力选择

| 实际可用能力 | 执行方式 | 证据限制 |
|---|---|---|
| 宿主提供浏览器技能/工具 | 阅读其实际说明，再用其打开、点击、截图与观察 | 操作和截图来自该浏览会话 |
| 已配置Playwright MCP等浏览器服务 | 按该服务工具schema执行导航、DOM定位、交互及截图 | 记录具体工具、时间、URL与动作 |
| 只有HTTP搜索或源码读取 | 继续项目识别、规则搜索和来源说明核实 | 标为未浏览验证，不能凑成20条已浏览候选 |
| 只有CLI，没有MCP | 运行本包CLI整理真实证据与生成报告 | CLI本身不会访问浏览器或调用LLM |

Codex提供 `browser:control-in-app-browser` 时遵守其技能，包括浏览器选择和能力边界。其他宿主不必安装这个Codex专用技能；使用自身浏览器接口。有重动效时一次只打开一个，截图描述外观，动效结论来自实际交互。

## 可选浏览器接入

没有宿主浏览器工具时，安装指南提供微软维护的 [Playwright MCP](https://github.com/microsoft/playwright-mcp) 配置。它是独立浏览器能力，用户按自己的客户端启用；本插件不会修改用户全局配置、读取登录凭据或自行启用后台服务。浏览器工具必须由调用智能体实际使用。

## 设计与审计

- 可用的 `frontend-design` / `impeccable` 优先复用，实际读取它们的说明。
- 未提供这些技能时，本插件自身的逐元素方案和UI UX Pro Max仍可调用。报告列出使用的技能与覆盖项，不把规则建议写成页面实测。
- 页面修改仍由宿主智能体执行，具体方案确认后实施。MCP工具只识别项目、检索规则、校验输入、生成报告和待确认方案，不提供自动修改网站的工具。
- 安装或MCP协议测试，只证明文件与调用链；没有运行某个客户端时，不宣称那个客户端已通过实际验收。
